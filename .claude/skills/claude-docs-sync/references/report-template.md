## 書き方の注意

- 各項目は **独立して採否判断できる** 粒度にする。
- best-practices.md 関連は重要文書である旨を明示し、慎重な確認を促す。
- 出典は必ず英語版の公式 URL を載せる。
- before/after は「要約」で良い (レポートを読みやすく保つ)。実際の全文差分はフェーズ2 で行う。

## 逆引き用の 2 欄 (`旧キーワード` / `波及ファイル`) — なぜ必須か

**2026-07-26 の同期でこの 2 欄が無かったために反映漏れが発生し、claude[bot] レビューで指摘された。**

- 事象: `fallback` の仕様変更 (一律 default Opus → カテゴリ別) を harness.md / model-comparison.md に反映したが、**best-practices.md の 5 箇所が旧仕様のまま残った**。
- 原因1 (レポート段階): 差分レポートの波及先を「model-comparison.md / harness.md」としか書かず、**best-practices.md を数え落としていた**。
- 原因2 (検証段階): 横断自己検証を **新しく書いた側の用語** (`カテゴリ別 fallback`) で grep したため、**旧記述 (`default Opus に fallback`) は原理的にヒットしなかった**。

したがって:

1. **`旧キーワード`** は「現状」側の表現から抜き出す。**新側の用語ではなく、消えるべき古い表現**を書く。これがフェーズ2 の逆引き grep の検索語になる。
2. **`波及ファイル`** はレポート作成時に**実際に grep して**列挙する。`doc_sources` のマッピングから推測してはならない (同一事実が想定外のファイルに散っていることがある)。

> **`旧キーワード` の選び方**: 「この表現が残っていたら古い」と言える最短の語句を選ぶ。長すぎると表記揺れで拾えず、短すぎると無関係な箇所を大量にヒットする。上記の例では `default Opus に fallback` が適切だった (`fallback` 単独では広すぎ、文全体では拾えない)。
