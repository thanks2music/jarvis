# doc-conventions.md — ドキュメント記述規約の詳細

JARVIS リポジトリの `docs/` 配下のスタイル規約。新規・更新いずれもこれに従い、既存ドキュメントと
浮かないようにする。

## 言語・文体

- すべて**日本語**で記述する。
- 文体は**常体 (だ・である調)** で統一する。「です・ます調」は使わない (会話と異なり文書は常体)。
- 技術用語は英語表記を維持する: ClaudeCode, MCP, GitHub, SubAgent, Hook, Skill, Plugin など。
- 半角・全角に注意する。数字・英字は半角。

## ファイル冒頭の出典ブロック

1 行目近くに必ず以下を置く。出典が複数あれば `/` 区切りまたは箇条書きで列挙する。

```markdown
> 出典: [ページ名](https://code.claude.com/docs/en/xxx) (YYYY-MM-DD時点)
```

複数出典の例 (harness.md / best-practices.md スタイル):

```markdown
> 出典:
> - [タイトル](URL)（補足）
> - [タイトル](URL)（補足）
> 最終更新: YYYY-MM-DD
```

- URL は**英語版 (en)** を載せる (正ソースが en のため)。
- `(YYYY-MM-DD時点)` は調査・更新した当日に更新する。

## 構成スタイル

既存ドキュメントの典型構成を踏襲する:

1. 冒頭: 出典ブロック + 1〜2 段落の概要
2. 「前提知識」節 (必要なら): 関連概念・他機能との比較表
3. 本体: 見出し階層 + テーブル中心。コードブロックは ` ```bash ` / ` ```json ` / ` ```yaml `
4. 「Tips」「ベストプラクティス」「アンチパターン」「トラブルシューティング」節 (内容に応じて)
5. 末尾: 「関連ドキュメント」節で相互リンク

## テーブル活用

このリポジトリは比較・対応関係をテーブルで示すスタイルが多い。「種別 × 用途」「Before/After」
「コマンド対応表」など、列挙情報はテーブル化する。

## ファイル名

- **kebab-case** の `.md` (例: `agent-teams.md`, `output-styles.md`)。
- 機能名をそのまま反映し、推測しやすい名前にする。

## 相互リンク

- 末尾「関連ドキュメント」で、関係する docs/ 内ファイルと公式ページにリンクする。
- 新規ファイルを足したら、関連する既存ファイルの「関連ドキュメント」にも逆リンクを追加するのが
  望ましい (双方向リンク)。

## README.md / CLAUDE.md への反映 (新規作成時)

新規 doc を作ったら必ず以下も更新する:

- `README.md`: 「Documentation」テーブル (英語版) と「ドキュメント」テーブル (日本語版) の**両方**に
  1 行追加する。
- `CLAUDE.md`: 「ドキュメント構造」のツリー図と「ドキュメント参照」の箇条書きリストの**両方**に
  追加する。

## モデル世代の書き方 (追記方式)

新モデルを反映する際は、旧世代の記述を削除せず追記する。harness.md の「モデル世代によるハーネス
進化のまとめ」テーブルのように、世代を行として積み増し、「何がどう変わったか」が追える形にする。
これは BOSS が進化の経緯を学べるようにするためで、このリポジトリの学習目的に沿う。
