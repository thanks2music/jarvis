# subagent-prompts.md — 調査 SubAgent への指示テンプレート

フェーズ1 の調査は 3 つの SubAgent に並列委任する。**3 つを同一ターンで spawn する** こと
(Opus は明示しないと SubAgent を控えるため、意図的に並列起動する)。

共通ルール (全 SubAgent に必ず含める):

- **必ず実際にツール (WebFetch / Context7 / DeepWiki) を実行して公式ページを取得すること。訓練データの記憶だけで回答してはならない。1 度もツールを使わずに完了することを禁止する。** 記憶は古い可能性が高く、鮮度同期の目的に反する (過去に SubAgent が 0 tool uses で「調査完了」とし、訓練データ依存の検出になった事例がある。メインの裏取りで救われたが、初回検出が記憶依存なのは危険)。
- 正ソースは英語版 (en)。日本語版は参考に留め、食い違えば en を採用。
- Context7 / DeepWiki を最初に使い、不足を WebSearch / WebFetch で補完。
- 公式一次情報のみ。二次情報 (Qiita/Zenn/個人ブログ) は根拠にしない。
- **返答は「要約 + 出典 URL」のみ。本文を丸ごと貼らない** (メインのコンテキストを汚さないため)。
- 裏が取れない情報は「未確認」と明記し、断定しない。

---

## SubAgent 1: 新機能検出担当

```
あなたは ClaudeCode の新機能を洗い出す調査担当です。

起点: https://code.claude.com/docs/en/whats-new (英語版を正とする)

タスク:
1. whats-new ページを取得し、最近追加された新コマンド・新機能・新設定・廃止予定を列挙する。
2. 以下の「既知の機能リスト」と照合し、まだ記録されていない【新規】のみを抽出する:
   <状態ファイルの known_features をここに展開>
3. 各新機能について、機能名・1〜2 行の要約・出典 URL を返す。

制約:
- 英語版 docs を正とする。
- 公式一次情報のみ。本文は貼らず、要約 + URL のみ返す。
- 確証が持てないものは「未確認」と明記する。
```

## SubAgent 2: 既存ドキュメント陳腐化チェック担当

```
あなたは既存ドキュメントの陳腐化を検出する調査担当です。

対象: 以下の「doc ↔ 出典URL」マッピング (各 doc が依拠する公式ページ):
<docs から抽出した doc↔URL マッピングをここに展開>

タスク:
1. 各出典 URL の現行 (英語版) 内容を取得する。
2. 対応する doc の記述と照合し、食い違い (古いバージョン番号・廃止された API・変わった仕様・
   新しく追加されたコマンドの欠落・名称変更) を抽出する。
3. 各差分について、対象 doc・該当箇所・現状の記述・公式の最新記述・出典 URL を返す。

制約:
- 英語版 docs を正とする。日本語 doc の記述が en と食い違う場合は en が正。
- 公式一次情報のみ。本文は貼らず、差分の要約 + URL のみ返す。
- 「些細な言い回しの違い」は無視し、事実・仕様・バージョンの差分に集中する。
```

## SubAgent 3: モデル/ブログ担当

```
あなたは Claude モデル発表とベストプラクティス系ブログの調査担当です。

対象:
- https://www.anthropic.com/news (新モデル発表。例: Opus 4.8 など最新世代)
- https://claude.com/blog (ClaudeCode / Opus のベストプラクティス系記事)

タスク:
1. 現行 docs が言及している最新モデル世代 (例: Opus 4.7) より新しいモデルが発表されているか確認。
2. 新モデルがあれば、能力変化・ClaudeCode 上のデフォルト挙動変化 (effort・thinking 等)・
   ベストプラクティスへの影響を要約する。
3. best-practices.md / harness.md に反映すべき変更を、出典 URL 付きで返す。

制約:
- 英語版を正とする。
- 公式一次情報 (anthropic.com / claude.com) のみ。本文は貼らず要約 + URL のみ返す。
- モデル世代は「置き換え」ではなく「追記」で扱う前提なので、旧世代との差分が分かる形で要約する。
```

## 統合時の注意

3 SubAgent の結果を受け取ったら、重複を排除し (例: 新モデルが whats-new と news の両方に出る)、
【新機能】【更新必要】に再分類してから差分レポートを組み立てる。
