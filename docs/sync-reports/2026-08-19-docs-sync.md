## 2. 検出漏れの原因究明

スキル本体（`avengers/dot-claude/global/skills/claude-docs-sync/`）を全文精読した結果、ソースの入口は **SubAgent プロンプト内の 3 つだけ**だった。5 つの原因が複合していた。

| # | 原因 | 根拠 |
|---|---|---|
| a | SubAgent 3 が「**モデル発表**検出器」として定義されていた | 役割行「あなたは Claude モデル発表と…担当です」/ タスク 1 が「新しい**モデル**が発表されているか」の条件ゲート / タスク 3 の出力契約が `best-practices.md`・`harness.md` 限定。製品発表が落ちる分岐が無い |
| b | 状態ファイルに製品発表を表現するフィールドが無い | SubAgent 3 へ注入されるのは `known_models` のみ。新モデルが無い回は差分が空で無言終了する。実際、2026-07-11 / 08-04 / 08-16 の 3 レポートは `anthropic.com/news` を **0 回**引用している |
| c | 索引面を変化検出に使っていない | sitemap / lastmod / RSS / llms.txt が未参照。`doc_sources` はモデル記事への deep link のみで、`introducing-claude-tag` のような**新 slug は原理的に発見不可** |
| d | 全走査を明示的に禁止していた | 旧 `SKILL.md`「全ページ全走査はしない。whats-new + 既存 docs が依拠するページ + モデル/ブログに範囲を絞る」 |
| e | 浮上してもスコープ判定で捨てられた | `docs/sync-reports/2026-08-16-docs-sync.md` §26 が「スコープ外 — Enterprise 向け機能」として Claude Tag を列挙。さらに**提案した `deferred_items` への記録が実行されなかった**ため、判定した事実ごと消えた |

### CLI 中心のソースでは構造的に拾えなかった

| ソース | "Claude Tag" のヒット数 |
|---|---|
| ClaudeCode CHANGELOG 全文 | **0 件** |
| whats-new 週次（w25〜w32） | **1 件のみ**（w29 の Artifacts 拡張に付随する言及） |
| `code.claude.com/docs/en/claude-tag` | **2026-08-10 に公開済み**（前回同期 08-16 の時点で既に存在） |

`claude-tag` ページは前回同期時点で既に生えていた。索引差分があれば検出できていた事例である。

## 3. スキル側の是正（avengers PR #19）

スキル本体は本リポジトリ外（avengers リポジトリ）にあるため、変更は別 PR で行った。

| 変更 | 内容 |
|---|---|
| `scripts/detect-new-sources.py`（新規） | sitemap / llms.txt の**決定論的な集合差分**でワークリストを生成する。Python stdlib のみ。**フェッチ失敗は exit 1** で止め、ネットワークエラーが「差分なし」に化けるのを防ぐ |
| `SKILL.md` 2-3 | ファンアウト前にスクリプトを実行する手順を新設。SubAgent は「探す役」から「機械検出済みのワークリストを判定する役」へ |
| `SKILL.md` 2-6 | **スコープ判定規則を明文化**（従来は成文化されておらずその場の判断だった）。プラン種別を判定材料にせず、「エンジン共有 / 設定継承 / 運用影響」の 3 条件で判定する |
| `subagent-prompts.md` | SubAgent 3 を「公式発表・ブログ担当」へ改称し全面差し替え。モデル限定フレーミングと条件ゲートを撤廃、out-of-scope も必ず返す契約に変更。SubAgent 1 に「新設 docs ページ」を起点として追加 |
| `state-schema.md` | `schema_version: 2`。`known_announcements` / `known_doc_pages` を追加し v1 からの移行手順を記載 |
| `workflow.md` / `report-template.md` | トリアージ結果の記録を**検証付きの必須手順**へ格上げ。検出全項目を「スコープ判定」表に載せ、out 判定は `deferred_items` へ書き込むところまでをチェックリストで確認する |

## 5. バックフィル（次回への申し送り）

`backfill_from: 2026-06-01` の窓で、**未トリアージの newsroom 記事が 62 件**検出された（うち 1 件が Claude Tag で本回に反映済み、**残り 61 件が未処理**）。
