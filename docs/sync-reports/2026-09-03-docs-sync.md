### 16. [既存追記・新節] Claude Tag のデータライフサイクル
- 追記先: `docs/claude-tag.md` の §2.3 直後、または §6 の後に新節
- 要点: 公式に **`claude-tag/concepts/data-lifecycle` が新設**された。JARVIS 側は「Anthropic 側に何が保存され、どの操作で消えるか」が**完全に未カバー**（既存 §2.3 は sandbox の揮発性のみ）。要点は 7 つ:
  1. **beta 中は自動 retention が存在しない**。明示的な削除操作まで保持され、**組織の custom data retention 設定は Claude Tag の transcript / memory に適用されない**
  2. 保存対象は 8 種（transcripts・memory・routines・scopes とその設定・Access bundles・account links・published artifacts・installation credential）
  3. **Slack 側でメッセージやファイルを消しても、既に transcript に入った内容は消えない**
  4. **「使わなくなる」では消えない**。プラン失効・Claude Tag の off・スコープの Off はいずれも無削除。削除には **workspace の disconnect** か **Slack からの uninstall** が必要
  5. 削除操作の粒度は 4 段階のみで、**単一スレッドの transcript だけを消す手段は存在しない**。beta 中は組織の data export に含まれず **Compliance API からも列挙・削除できない**
  6. **セッションは削除ではなく archive される**（`!restart` 後の旧セッション、約 1 時間の沈黙で置き換わる channel-level セッション等）。既存 §2.1「スレッド = 1 セッション」の理解を補正する
  7. **pairing 後に ZDR を採用しても既存データは消えない**
- 出典: https://claude.com/docs/claude-tag/concepts/data-lifecycle
- 重大度: 中（セキュリティ・削除要求に直結する情報が一次情報に存在するのに対応節がない）
